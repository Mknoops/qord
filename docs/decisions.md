# Decisions

Decisions made while building Qord, newest last. Each says what was decided
and why, so it can be revisited deliberately.

## 2026-10-07: setup and batch 1

1. **Base pinned at Acheron `e0191a1696e72c800c629527dbec5e0671ff654e`** (2026-10-06), as surveyed. Upstream remote stays `origin`; Qord work lives on the `qord` branch.
2. **C++20, not C++23.** Acheron builds as C++20 and its CI covers MSVC, GCC on Ubuntu 22.04 (AppImage) and Apple Clang. Nothing in batch 1 needs C++23; raising the standard would be a portability risk for no gain. Revisit when a feature needs it.
3. **vcpkg tool on VS 2026.** The vcpkg tool pinned by the submodule (2025-06-02) does not recognize VS 2026's v145 toolset; the newest tool (2026-09-26) rejects the pinned scripts' schema. Locally, `vendor/vcpkg/vcpkg.exe` is vcpkg-tool `2025-12-16` (Microsoft-signed). The submodule and package baseline are unchanged; CI is unaffected (it bootstraps on its own image).
4. **Inventory facts are computed, and one stated fact was wrong.** The brief said 7 plugins are `required` + `enabledByDefault`. The pinned file has 7 `required`, 7 `enabledByDefault`, and 0 with both. `docs/equicord-source-version.md` reports the computed numbers. `target`, `dependencies` and `commands` are optional fields (present on 28, 89 and 15 entries).
5. **Manifest `dependencies` lists Qord plugin ids.** Equicord's dependencies on API plugins (`MessageEventsAPI`, `MessagePopoverAPI`, ...) are host features in Qord, not plugins, so they are not listed. The host enables a plugin's dependencies with it and disables dependents with their dependency.
6. **Permission grants.** Enabling a plugin in the Plugins page asks once for the permissions it declares but hasn't been granted; each can be revoked individually afterwards. Plugins marked `enabledByDefault` get their declared permissions on first run only (a user's later choice sticks). A hook is dispatched only if its permission is declared *and* granted; `PluginContext` hands out services (network, member roles) only when granted.
7. **Hook dispatch order is plugin id order**, so results don't depend on registration order.
8. **Plugin state** lives in `%APPDATA%/ouwou/Acheron/plugins/`: `host-state.json` (enabled, grants), `settings-<id>.json`, `data/<id>/` (caches). App name and data directory stay Acheron's for now so upstream changes merge cleanly; renaming the app to Qord is a branding decision for the project owner.
9. **Reply pings.** Acheron had no reply-ping control: every reply pinged. Qord adds Discord's `@ ON/OFF` toggle to the reply bar. Clicking Reply defaults to ping unless Shift is held (Discord's behavior), then `shouldMentionOnReply` plugins may decide. When the ping is off the send request carries `allowed_mentions: {parse: [users, roles, everyone], replied_user: false}`, the same shape the official client sends; when it is on the request is unchanged from Acheron's.
10. **Received-message transforms** (`transformIncomingContent`, used by TextReplace's "others' messages" scope) run in `MessageManager::parseMessageContent`, change only the rendered HTML, and never the stored message. Synthesized system texts are not passed to plugins. Messages already rendered update when the channel is re-rendered; upstream also only applies changes on re-render.
11. **Sending an empty result.** If `onBeforeSend` plugins reduce a message with no attachments to whitespace, nothing is sent (Discord would reject it).
12. **Fidelity testing.** Ported logic is checked against golden outputs produced by running the upstream plugin code under Node.js (`tests/plugins/data/generate-*.mjs`). Node is a development aid only; nothing at build or run time uses it.
13. **JavaScript semantics.** `src/Plugins/JsCompat` reproduces what ported code relies on: RegExp flags (`g i m s y`), `$&`/`$1`/`$<name>`/`` $` ``/`$'`/`$$` substitution, `\uXXXX`/`[^]`, end-of-input `$`, JS whitespace and `trim`.
14. **ClearURLs** fetches ClearURLs' `data.min.json` (no bundled copy), caches it, and refreshes at start when older than 7 days. The client's network service only allows HTTPS, caps responses at 16 MiB and allows at most 5 same-or-safer redirects. Providers are applied in file order like upstream (`QJsonObject` would sort them).
15. **NoReplyMention** matches ids exactly; upstream does a substring test on the raw text (`"12,34".includes("2")`), which can match partial ids. Default lists are empty instead of upstream's placeholder ids; behavior with empty lists is the same.
16. **NormalizeMessageLinks** is ported and wired, but Qord's Copy Message Link already produces `discord.com` links (there is no canary/ptb build to inherit a host from), so it has no visible effect today. Kept for parity and for any future host choice.
17. **Unindent's display half is a gap.** Upstream also unindents code blocks when rendering. Acheron's Markdown parser renders ``` blocks through the inline-code rule and has no code-block node to hook. This is recorded as a manifest `gap`, so Unindent cannot reach Complete until Qord has a fenced code-block renderer. That renderer is shared infrastructure many plugins will need.

## 2026-10-07: batch 2

18. **Two shared UI surfaces.** *Chat bar buttons* (`chatBarButtons` hook): plugins return buttons (id, tooltip, SVG icon, active) for the current channel; clicks go back to the plugin; a plugin calls `PluginContext::refreshChatBar()` when its buttons change. They sit to the right of the message box (`UI/Input/PluginChatButtons`) and are re-queried on channel switches. *User context menu items* (`userContextMenu` hook) are appended after "Copy User ID". Both need the new `add_ui_elements` permission; copying needs `write_clipboard` (`PluginContext::clipboard()`).
19. **`@silent` in the base client.** Discord's web client turns a leading `@silent ` into the `SUPPRESS_NOTIFICATIONS` flag and strips it; Acheron sent it as text. Qord's send path now does the same after plugins run, which SilentMessageToggle relies on.
20. **Hidden settings** (`"hidden": true`) hold plugin state that should persist but has no editor (SilentMessageToggle's last state).
21. **Randomness is injectable.** Plugins that use `Math.random()` (Ingtoninator, PolishWording) take a random source so tests replay upstream's exact draws.
22. **JS helpers** gained `split` (ES `@@split` semantics, captures spliced in), `test`, and `replace` with a callback.
23. **Behavior fixes kept deliberately small and noted per plugin**: TalkInReverse reverses by grapheme (upstream breaks emoji); WriteUpperCase ignores empty blocked words (upstream's empty setting blocks everything); SilentMessageToggle's "persist between restarts" restores the saved state (upstream starts every channel switched on); PolishWording leaves a hand-typed `__CODE_BLOCK_n__` alone (upstream writes "undefined"). PolishWording's sentence splitter, which upstream wrote so it can never split after a period, is ported unchanged because that is the behavior users get.
24. **DontRoundMyTimestamps deferred.** Acheron does not render Discord's `<t:…:R>` timestamps, so there is nothing to round yet. It needs a timestamp-markdown surface first.

## 2026-10-07: batch 3 (most-used plugins)

25. **Message surfaces.** `messageContextMenu` (plugin items, including submenus, in the message right-click menu; the context carries the right-clicked image URL and the message as JSON), `messageHistory` (keep a deleted message, see edits, annotate a message for rendering) and `messageFilter` (hide a message; or keep it visible but silent). New permissions: `log_messages`, `hide_messages`, `read_relationships`, `open_links`. New services: relationships (blocked/ignored), UI (read-only text dialog, open an http(s) link), messages (re-render, remove a kept message, re-filter).
26. **Annotations are data, rendering is the client.** Plugins return a `MessageAnnotation` (deleted + style, edit history, diffs); the client renders it with its own Markdown renderer. Plugins stay UI-free and the look stays consistent. The diff algorithm (`TextDiff`) is shared in the host library.
27. **Kept deleted messages are temporary.** The client still records the deletion in its database, so a kept message disappears after a restart or when MessageLogger is disabled, matching upstream ("temporarily logs"). Kept messages lose reply/edit/delete/pin/react actions.
28. **Hidden messages are hidden rows**, not removed from the model, so history paging anchors keep working; hidden and silenced messages do not mark the channel unread.
29. **SilentTyping deferred.** Acheron never sends typing indicators, so the plugin's effect is already the default. Porting it needs the base client to send typing first (a behavior change worth deciding separately).

## 2026-10-07: Discord look and core Discord features

30. **Local mock server for UI work.** `tools/mock_discord.py` (standard library only) serves a fake gateway (zlib-stream WebSocket), REST API and CDN with sample servers, channels, members and messages. `QORD_MOCK_DISCORD=http://127.0.0.1:<port>` (`tools/run-mock.ps1`) makes the client use a separate `Qord-Mock` profile, one fake account and a placeholder token, and rewrites Discord CDN hosts to the mock. Only loopback URLs are accepted (`src/Qord/DevMock.cpp`), so mock mode cannot talk to Discord. This is how Qord's UI is checked without logging into a real account. It does not prove compatibility with the real API, which still needs a logged-in check.
31. **Discord's look is the default.** The default palette is Discord's dark theme (chat #313338, sidebars #2b2d31, server rail #1e1f22, blurple accents), with new theme tokens for these surfaces so the Appearance page and the theme generator still control them. The server rail (Acheron's "classic" mode) is the default layout. Users who had chosen the tree keep it. Discord's sizes are matched: 72px rail with 48px icons that turn rounded on hover/selection, round 40px chat avatars, 32px member-list avatars, uppercase category headers, muted read channels, rounded hover/selection, red mention badges, a gold highlight on messages that mention you, and a borderless rounded message box with an upload button. The menu bar is hidden like Discord's; the user panel menu can show it, and its shortcuts keep working.
32. **User panel.** Bottom-left like Discord: avatar with status, name, status line, plus mute, deafen and settings. Mute/deafen are new to the client (Acheron had none): they send the voice state flags, zero the input gain/output volume, and apply to calls joined later. Status (online/idle/dnd/invisible) and a custom status are sent over the gateway (op 3) and saved to the user's settings proto like the official client.
33. **Core Discord features added to the client** (`src/Qord/ClientExtras.cpp`, declared in Acheron's `Client`): the typing indicator (one request per ~9s while typing, cleared on send), pinned messages, message search (guild or DM, `from:`/`in:`/`has:` filters), the mentions inbox, friend requests and relationship changes, invite lookup/join, server and channel creation, and per-server notification settings. The channel header gained Discord's pins, member-list toggle, search and inbox. UI for friends, invites, server creation and notification settings follows.
34. **Typing indicators change SilentTyping's status.** The base client now sends typing like Discord, so SilentTyping (decision 29) is no longer a no-op and can be ported as a real plugin.
35. **Markdown completed to Discord's rules** (`src/Core/Markdown/QordRules.cpp`): fenced code blocks, block quotes (`>` and `>>>`), headings, `-#` subtext, list items, `||spoilers||` (click to reveal), `<t:…>` timestamps in all seven styles, role mentions in the role's colour, `@everyone`/`@here`, and slash-command mentions. Rules follow Discord's patterns, including only matching block syntax at the start of a line. This closes the render-side gap behind Unindent (decision 17) and the timestamp surface DontRoundMyTimestamps needed (decision 24).

36. **More core Discord features.** An emoji picker (frequently used from the synced frecency data, each server's usable emoji with the current server first, all Unicode emoji, search) for the message box and Add Reaction, which Acheron left unimplemented; a react button on the hover bar; a Friends page on Home (Online/All/Pending/Blocked, Add Friend, accept/ignore/cancel, remove, unblock, message); "Add a Server" (create, or join with an invite link or code); mute and notification-level menus on servers, channels and DMs; desktop notifications for DMs and mentions (tray toast plus taskbar flash) that skip Do Not Disturb, muted servers/channels, messages plugins silence, and the channel you're looking at. The notification setting is `notifications/desktop` (on by default).
37. **Menu extension points.** Server and channel right-click menus take an extender callback from the window. Mute and notification items use it, and it is the surface plugin channel items (e.g. MessageLogger's "Clear Message Log") will use.

## 2026-10-08: batch 4

38. **Five new hooks.** `typing` (whether to send your typing indicator, whether to show others typing; permission `control_typing`), `linkWarnings` (skip the confirmation before opening a link; `trust_links`), `notifications` (hold back a desktop notification; `control_notifications`), `authorNames` (the name shown for a message author or reply author; `modify_displayed_messages`) and `channelContextMenu` (items on server and channel menus; `add_ui_elements`). For yes/no hooks any plugin saying no wins. Chat bar buttons now report left, middle or right clicks.
39. **New services.** UI: insert text into the message box, a timestamp picker, a one-line text prompt, open a plugin's settings page. Message actions (`edit_messages`): change a message's flags on Discord. Display options (`modify_displayed_messages`): relative-timestamp rounding. Callbacks from dialogs are dropped if the plugin has stopped.
40. **Display plugins re-render what is on screen.** When a plugin that transforms received content (TextReplace, Unindent) or display options (DontRoundMyTimestamps) is toggled or reconfigured, the visible messages are re-parsed from their stored content. Decision 10's "on re-render only" no longer applies.
41. **Relative timestamps follow moment.js.** `<t:…:R>` uses moment's thresholds, calendar-month durations and rounding, checked against moment.js 2.30.1 on 124 distances (tests/qord). DontRoundMyTimestamps switches rounding to floor, as upstream does.
42. **Closed gaps.** MessageLogger now offers "Clear Message Log" on channels (decision 25's pending surface). Unindent now unindents received code blocks when shown, completing decision 17.

## 2026-10-09: batch 5

43. **Four new hooks and two permissions.** `serverListButtons` (text buttons above the servers; `add_ui_elements`), `memberCounts` (the numbers above the member list and in a server's tooltip; `add_ui_elements`), `userDecorations` (icons after a user's name in the member list, message headers and profiles; new permission `read_presences`, since the context carries the user's platforms) and `profileImages` (a click on a profile's avatar or banner; `add_ui_elements`). New services: `ReadStateService` (`mark_read`: mark every server read, the same bulk acknowledgement as Discord's Mark As Read), `UiService::openImage` (the image viewer, limited to Discord's CDN hosts) and a display option for the phone-shaped status dot. User and channel menu contexts now carry avatar, icon and banner URLs.
44. **Decorations are SVG plus a colour.** Plugins return an SVG document and either `#rrggbb` or `status:<status>`, which the client resolves to the theme's status colour (upstream's `useStatusFillColor`). The client renders and caches the pixmaps, drops the cache for users whose presence changes, and shows each icon's tooltip. SVGs keep their aspect ratio like a browser's default `preserveAspectRatio`.
45. **Unset ids reach plugins as 0.** Acheron's unset `Snowflake` is ~0, and several call sites passed it straight into plugin contexts (e.g. the server id in DMs, the channel id on a server's menu). The plugin API has always documented 0 for "none"; `Qord::Plugins::pluginId()` now converts at every call site and in `toMessageContext`. Plugins from earlier batches that compared ids to 0 now behave as documented.
46. **Base Discord details.** Message headers show Discord's APP tag on bots, the time as "Today at 3:45 PM" / "Yesterday at …" / date and time, and a full-date tooltip; the profile popup's BOT tag is now APP. The image viewer fits images opened without a preview.
47. **Mock checks for batch 5.** In the mock client (decision 30) all four plugins were enabled and observed: Read All cleared two unread servers with one bulk ack of 4 channels; the member list header showed online/total/in-voice and the server tooltip online/total; platform icons and tooltips appeared in messages, the member list and the profile, own icons came from the session list, and a mobile user who is idle got the phone-shaped dot; View Avatar, View Icon and a click on a profile avatar opened the viewer. This is not `verifiedInClient`, which needs real Discord traffic, so the four plugins stay Tested.
48. **Qt 5 build fixed.** The batch 4 SilentTyping test did not compile on Qt 5.15 (ambiguous `QStringList` assignment); it and the new tests now build on both, and voice-dependent counting is compiled out with `ACHERON_NO_VOICE`.

## 2026-10-09: batch 6 and 7 (in progress)

49. **The build deploys the Qt runtime.** `tools/build-windows.ps1` runs `windeployqt` on `buildcheron.exe` (and copies the FFmpeg DLLs), so the app starts when double-clicked. Before, it only started with Qt on PATH (`run-mock.ps1`), and Windows reported the first missing DLL (Qt6Svg.dll).
50. **The NEW divider.** Opening a channel remembers what was read at that moment (`ReadStateManager::ackIdWhenOpened`); the first message after it gets Discord's red line with a NEW tag, and starts a new message group. Sending a message removes it, like Discord. Date dividers now use Discord's style (thin line, long date in the middle) and turn red when they coincide with NEW.
51. **Notification sound and a Notifications settings page.** New DMs and mentions that pass the notification rules (decision 36) play a short chime; it is synthesised in code (two notes), not Discord's sound file. It plays through miniaudio when the client has it and falls back to the system beep. Settings gained a Notifications page: desktop notifications and the message sound, each on by default, with a Play button.

52. **Voice states hook.** `voiceStates` (new permission `read_voice_states`) tells plugins when someone joins, moves between or leaves voice channels (your own connection included), and lets them add text to voice participants in the channel list (after the name, or as a clock icon with a tooltip) and to the voice connection panel. Contexts carry the time, so plugins are testable without a clock; the client repaints these once a second while a plugin uses the hook. CallTimer is the first user; its duration format is checked against Equicord's `formatDurationMs` run in Node.

53. **GIF and sticker pickers.** The message box gained Discord's GIF and sticker buttons. One popup has GIFs / Stickers tabs plus an Emoji tab that opens the emoji picker. GIFs come from Discord's Tenor proxy (`/gifs/trending-gifs`, `/gifs/search`) and are sent as their link through the normal send path, so plugins, slowmode and replies apply. Stickers are the current server's (`/guilds/{id}/stickers`) and are sent with `sticker_ids`. Not covered yet: Discord's built-in sticker packs, other servers' stickers with Nitro, animated previews (the picker shows still images), and Lottie stickers (shown by name). The endpoints follow Discord's web client and are only exercised against the mock so far; the buttons were seen in the mock client, but the pickers were not clicked through there yet.
54. **CallTimer seen in the mock.** With "All call timers" and "Show without hover" on, the timer counted next to a user in a voice channel. The connection timer needs a voice connection, which the mock cannot provide.

55. **Slash commands.** Typing `/` loads the server's (or DM's) command index (`/guilds/{id}/application-command-index`, `/channels/{id}/application-command-index`) once per place and lists matching commands with their descriptions; Tab or Enter picks one, and after the name the menu shows the options (`/remind what: minutes: [dm:]`). Sending `/name [group] [sub] option:value …` posts an application command interaction (`/interactions`, type 2, with the gateway session id) instead of a message; values are checked and converted by option type (numbers, booleans, user/channel/role mentions, choices), and a mistake keeps the text and says what is wrong. Text that names no command is sent as a message, as in Discord. Answers show Discord's "<user> used /name" line. The parsing is unit tested (`tests/qord/tst_slash_commands.cpp`); the requests were written against Discord's web client behaviour and the mock, and have not been run against Discord yet. Not covered: attachment options, autocomplete options, per-command permission filtering (Discord rejects what you may not use), user-installed apps outside servers, and context-menu (user/message) commands.

56. **Message clicks hook.** `messageClicks` (`add_ui_elements`) reports every press in the chat and each click on a message with its count (single/double/triple, like the browser's `event.detail`), the keys held (Shift/Ctrl/Alt, and Backspace/Delete tracked app-wide), the user's permissions in the channel, the message's pinned state, your reactions and the selected text. Message actions gained delete, pin/unpin and reactions (`edit_messages`), and the UI service can start editing a message or a reply (with or without a ping, or Discord's default). MessageClickActions is the first user; its click timing is the upstream logic, run with real timers in its tests, and its emoji/quote helpers are checked against upstream in Node.

57. **Reactions hook (groundwork).** `reactionUsers` (`read_reactions`) lets a plugin say which users to show on a reaction, and hears live reaction changes; the reaction service fetches a reaction's users (scoped, so replies after a plugin stops are dropped). WhoReacted will be its first user.

58. **Expressions service, cancellable sends and display parts (FakeNitro).** `read_expressions` gives plugins your servers' custom emojis and stickers, your Nitro type, your roles and your channel permissions, and lets them unlock the emoji picker and autocomplete (for messages, never reactions) and the sticker picker. Outgoing messages carry the sticker being sent and a `cancel` flag; a cancelled send leaves the text and files in the message box. Received messages expose their attachments and embeds, and display hooks can hide some of them and add stickers; this is recomputed every time the message is parsed and never changes the stored message. The UI service gained a modal confirmation (with an optional checkbox) and adding a file made in memory to the message box. Qord now keeps the stickers of every server from the gateway, so other servers' stickers can be offered with Nitro or FakeNitro.

59. **FakeNitro's animated stickers.** Upstream redraws APNG stickers on a canvas and encodes a GIF with gifenc. Qord reads the APNG the same way (upstream's apng.ts), draws the frames with QPainter and writes the GIF with its own small encoder (median cut palette, GIF LZW). Transparency is kept by alpha, where gifenc's palette does not keep it; the output is therefore not byte-identical to upstream's, and the tests check the frames by decoding them with Qt's GIF reader.

60. **Go Live (screen sharing and watching streams).** Discord's voice protocol carries video next to audio: Identify asks for a video stream (`video`, `streams`), Ready returns its SSRCs, SELECT_PROTOCOL offers H.264 (payload type 101, RTX 102), op 12 announces the stream (resolution, frame rate, bitrate) and op 15 asks the server to forward video. Starting a stream sends STREAM_CREATE and STREAM_SET_PAUSED on the main gateway; STREAM_CREATE / STREAM_SERVER_UPDATE give the RTC server, endpoint and token for a second voice connection used only for the stream. Watching sends STREAM_WATCH and opens a receive-only connection. Video packets use the same rtpsize AEAD as audio, with the one-byte header extension (playout delay) Discord's clients send: the 4-byte extension header is additional data, its body is encrypted with the payload. Frames are DAVE-encrypted as whole access units by libdave (it keeps H.264's NAL headers readable) before RTP packetization (single NAL units and FU-A; STAP-A is understood on receive). Lost packets drop the frame and ask for a keyframe (RTCP PLI); keyframe requests from the server force one, and a keyframe is also sent every 3 seconds because not every encoder keeps its GOP size.

61. **Encoding and capture.** H.264 Constrained Baseline without B-frames, through ffmpeg: NVENC, AMF and Quick Sync first, then OpenH264, then Media Foundation (last, because it ignored forced keyframes here). Screens are captured with DXGI desktop duplication (GDI as fallback) and the cursor is drawn in; windows with Windows.Graphics.Capture (GPU, 30 fps measured, against about 19 fps with PrintWindow, which remains the fallback). The quality choices follow Discord's limits: 720p up to 30 fps without Nitro, 1080p 60 fps with Nitro or a server at boost level 2, higher resolutions with Nitro.

62. **Testing video without Discord.** The mock server has a voice gateway and a UDP media server. It relays packets like an SFU, decrypts Qord's stream itself (AES-GCM with Windows' BCrypt), reassembles it with a separate RFC 6184 implementation and writes it to a file that ffmpeg decodes; and it streams an ffmpeg test picture as "Ava" for Qord to watch. Both directions work there. What the mock cannot show is whether Discord's servers accept the stream: DAVE, the exact Identify/op 12 fields and RTCP handling are only checked against Discord's documented behaviour and other clients' implementations, not against Discord itself.

63. **Click to join, click to watch.** As in Discord, a plain left click on a voice channel joins it (unless already in it) as well as opening its chat, and clicking a participant who is live opens their stream. The right-click menu entries stay. Acheron opened its Voice Settings window on every connect; Discord shows nothing extra, so in Qord that window opens only from the voice panel.

64. **Cameras in calls.** Cameras ride on the call's own voice connection, not a second one as Go Live does. With video supported (`VoiceManager::setVideoSupported`, switched on where video is built), that connection asks for a `video` stream in Identify and offers H.264 in SELECT_PROTOCOL, so Ready gives it a video SSRC. Turning the camera on announces it with op 12 and sets `self_video` in the main gateway's voice state; the call connection's speaking state stays the microphone's (only a stream connection marks itself speaking for video). Op 15 asks the server for everyone's video as soon as the call connects, and each camera is decoded on a thread of its own, one decoder per SSRC; op 12 with no SSRC, or the user leaving, ends their tile. VideoSender now takes any `FrameSource`, so screens and cameras share the capture/encode loop: 720p30 at 2.5 Mbit/s, the camera's aspect ratio kept, never scaled up. Capture: Media Foundation on Windows (a source reader with video processing, so MJPEG and YUV cameras both arrive as RGB32; the mode closest to 720p30 is chosen first), V4L2 on Linux (YUYV converted in Qord, MJPEG through Qt's JPEG reader). No ffmpeg avdevice: it would bring back the 33 MB of DLLs ffmpeg.cmake leaves out. Your camera stays on when you move channels and goes off when you leave. The self view is mirrored, as in Discord. In mock mode only, a test-pattern camera is listed first, and the mock's "Ava" has her camera on (colour bars). x264 is now the last encoder fallback, for Linux distributions whose ffmpeg has it but not OpenH264. Checked against the mock on Linux (both directions; ffprobe reads Qord's 1280x720 stream). Not checked: real cameras (none in the cloud machine; the Media Foundation path has not been compiled yet), and Discord's servers.

65. **No credentials in logs.** Acheron logged every main and voice gateway payload at debug level, which put voice and stream server tokens, the voice session's `secret_key` and READY's `analytics_token` in the log, and an info line printed the first 8 characters of each voice token. Payloads now go through `Core::redactSecrets` before they are logged: the values of `token`, `secret_key`, `analytics_token`, `ticket`, `password`, `new_password` and `authorization` are replaced at any depth (a null stays null, and text that isn't JSON is logged only as its size). The redaction runs only when the debug category is on, because `qCDebug` evaluates its arguments only then. The info line no longer mentions the token. The account token itself was not seen in the logs: Identify is sent without being logged.

66. **Go Live sound.** A stream sends what the computer plays as Opus on the stream's own voice connection (48 kHz stereo, 128 kbit/s, music, DTX, so silent frames aren't sent); after a pause in sending, the RTP clock is snapped back to the wall clock, as at the start of speech. Windows captures with process loopback (Windows 10 2004 and later), the way Discord does: a shared window sends that program's sound (and its children's), a shared screen sends everything except Qord's process tree, so the call never echoes into the stream. Linux captures PulseAudio's/PipeWire's `@DEFAULT_MONITOR@` through miniaudio. That monitor also carries Qord's own sound, so on Linux "Share sound" starts off (the choice is remembered) and its tooltip says so. Watched streams' sound is mixed into the call's output pipeline, so it follows deafen, the output device and the output volume. Each stream's SSRCs get their own key space there, because they come from another RTC server and could equal the call's. If sound capture fails, the picture keeps streaming and a message says why. Checked on Linux against the mock with a PulseAudio null sink: Ava's stream tone plays through the call output, and Qord's stream carries a tone played on the system. The Windows loopback compiles under MinGW with a stand-in for `audioclientactivationparams.h`; it has not been built with MSVC or run.

67. **Video packet pacing.** An encoder returns a whole frame at once, and a 720p keyframe is around a hundred RTP packets; sent in one burst, they overflow router and Wi-Fi queues, which loses packets, which asks for more keyframes. Packets now leave through a leaky bucket at 2.5 times the announced video bitrate (WebRTC's pacing factor; at least 2.5 Mbit/s), with at most 5 ms of unused rate saved up, so an ordinary frame still leaves well inside its frame interval. When the queue holds more than 250 ms of sending, the pacer lets everything go, because late video is worse than bursty video. Packets are sealed (and DAVE-encrypted) before they are queued, so order and nonces are unchanged; audio isn't paced. Applies to both Go Live and cameras. UserVoiceShow follows upstream: a speaker after the name of anyone in voice (locked when you can't see or join the channel, else deafened, else muted), in profiles, the member list and messages (each a setting), with a tooltip "In Voice Chat", the channel and who is there (13 at most, then "+N"); channels you can't see are left out unless ShowHiddenChannels is on. A click opens the channel after 250 ms unless a double click joins it instead, or says "You cannot join the user's Voice Channel" without Connect. The tooltip lists names rather than upstream's avatars, and the indicator isn't on the Friends page's rows yet, where upstream adds it as a row button. Unit tested and checked against the mock (Ava in the Lounge). Not checked against Discord.

93. **ShowConnections; compact connections.** `DisplayOptionsService::setCompactConnections` turns a profile's connections list into a row of icons that wraps (a new `FlowLayout`), with an icon size and gap; each icon's tooltip is the account name, a check when verified, and what a click does: open the account's page (Qord's existing platform links), open Xbox's player page, or copy the name with Discord's "Copied to clipboard!" toast. A lookup the plugin passes in adds a GitHub account's organizations after it, as upstream does, each drawn with the GitHub icon and opening the organization's page. ShowConnections follows upstream's settings (icon size, Compact/Cozy/Roomy margins of 4, 6 and 8 px, GitHub organizations on by default) and asks GitHub's public API (`api.github.com/users/<name>/orgs`, no key) under the `network` permission, once per name while Qord runs where upstream asks each time a profile opens; a failed request shows none and is asked again next time. Qord has one profile window that already lists connections, so the plugin restyles that list, and "Show on profile modal" has nothing to switch. The mock gives Ava five connections and answers the GitHub request itself (the mock rewrites `api.github.com`), so checking it never reaches GitHub. Unit tested (settings, the request, caching, failures, stopping, the layout) and checked against the mock (the icons, tooltips, the organizations and copying). Not checked against Discord.

94. **Role Colors setting; BetterRoleDot.** Appearance gains Discord's accessibility setting "Role colors": show them in names (the default, as before), next to names, or not at all. "Next to names" draws names in the normal text color with an 8 px dot in the role color after them, in message headers and the member list; Qord draws a circle, as Discord's dot looks, rather than tracing Discord's own shape. Profile roles now start with a dot in their color, as Discord's role pills do. `DisplayOptionsService::setRoleDot` makes dots copy their color (`#rrggbb`, with "Copied to clipboard!") when clicked, which BetterRoleDot turns on, as upstream's patch does for every role dot; its "Both styles" keeps names in their role color next to the dot, whatever the setting (upstream turns both of Discord's checks on), and "Copy role color in profile popout" makes the profile's role dots copy too, as Both styles also does. Discord's setting isn't synced from Discord; Qord keeps it locally. Unit tested (the rules, the plugin's settings) and checked against the mock (dots in messages and the member list, copying from both and from a profile role, the setting). Not checked against Discord.

95. **64-bit hooks; ImplicitRelationships.** The `Hook` flags outgrew 32 bits; `Hooks` is now Qord's own 64-bit flag set (QFlags holds at most 32 bits on Qt 5), used the same way. A new hook, `friendsSections` (with `read_relationships`), adds tabs to the Friends page after Blocked: a label, a count title, an empty-state text and the people in the plugin's order (or by name), shown with their status and a Message button; the page asks Discord for people it doesn't know in every server you are in (op 8, 100 at a time, once each per account) and shows them when they arrive, and tells plugins when it opens. `RelationshipDirectory` can now say whether you have any relationship with someone and fetch Discord's user affinities (`GET /users/@me/affinities/v2/users`: who Discord ranks you as talking to, with a communication rank). ImplicitRelationships follows upstream: an "Implicit" tab ("IMPLICIT — N") of people you have an affinity for and no relationship with, fetched each time the Friends page opens, closest first or, without "Sort by affinity", by name, with the Online tab's empty text; upstream's patches to Discord's member request nonce have no counterpart, as Qord tracks the requested users itself. The mock answers the affinities with a friend, a request, dan and a stranger and now answers op 8 with only the requested members. Unit tested and checked against the mock (only dan is listed; the stranger, in no shared server, is asked for and stays hidden). Not checked against Discord.

96. **Contributor tooling; generated README lists.** The README's plugin table, its "Up next" line and the plugin count are now generated by `tools/check_equicord_plugins.py --write-docs` from the manifests (a new optional `summary` field gives each plugin its README line) and from `data/equicord/roadmap.json`, a hand-ordered list of the plugins to port next, most useful and popular first, each with its effort, what the client still lacks for it, and whether it is a *good first plugin* (the existing API covers it). The roadmap also renders `docs/roadmap.md`, and the hook table in the new plugin guide (`docs/writing-plugins.md`) is generated from `Permission.cpp`, the manifests and a one-line description per hook that the tooling tests require; CI's existing `--check-docs` keeps all of them current. `tools/new_plugin.py <EquicordName> --hook ...` scaffolds a port from the pinned inventory: the manifest with upstream's path, description and authors, the permissions its hooks need, a plugin class with `hooks()` filled in, a test and both CMake entries. Its test carries a `QORD_SCAFFOLD_TEST` marker, and a plugin whose test still has it counts as Implemented, not Tested, so an unwritten test can't inflate the numbers. `CONTRIBUTING.md`, issue forms (bug report, plugin request) and a pull request template describe the setup, the mock, the house rules (no browser engine or JS runtime, no telemetry, no logged tokens, honest permissions) and what a pull request needs.

97. **User panel buttons, activity settings; GameActivityToggle.** A new hook, `userPanelButtons` (with `add_ui_elements`), puts plugin buttons before mute and deafen: an SVG icon in the theme's icon color, a tooltip, an optional red glow (Discord's look for a switch that is off), a click, and a right-click menu of plain or checkbox items; the panel asks again when a plugin calls `refreshUserPanel()` or Discord's settings change. A new permission, `control_activity` ("Change whether others see what you play or listen to"), gives an `ActivitySettingsService`: Discord's synced "Share your detected activities with others" (`status.show_current_game` in the settings proto, written with a partial PATCH and shown at once), your connected accounts (`GET /users/@me/connections`), and whether one shares its activity (`PATCH /users/@me/connections/{type}/{id}`). GameActivityToggle follows upstream: "Disable Game Activity" / "Enable Game Activity", the old and new icons, and with Spotify connected a right-click menu of "Share Spotify Activity" items (named per account when there are several, revoked ones left out) that show a change at once. Qt's SVG renderer has no masks, so the off icon lacks the gap upstream cuts around its slash, and there is no Equicord Toolbox to move the button to. It is the first plugin started with `tools/new_plugin.py`. Unit tested and checked against the mock, which now has your own Spotify and GitHub connections. Not checked against Discord.

98. **Devices settings, plugin notifications; BetterSessions.** Settings gains Discord's Devices page: the devices logged in to the account (`GET /auth/sessions`), the current one first (READY's `auth_session_id_hash`) and the rest by last use, each with an icon (computer or phone), "OS · Platform", the location and "3 hours ago", log out for one (`POST /auth/sessions/logout`) and "Log Out All Known Devices", each after a confirmation. A new hook, `deviceSessions` (with a new permission, `read_sessions`: "See the devices logged in to your account"), lets a plugin restyle a device (title, a NEW badge, the icon's colour, a round badge on it, a tooltip on the time) and add buttons to it, and tells it when the page closes and when Discord reports the account's sessions: after it connects, and whenever the set of sessions in SESSIONS_REPLACE changes (a device logged in or out), so plugins never need to poll. `SessionService` fetches the sessions and refreshes the page. Plugins can now show notifications, as Vencord's `showNotification`: cards stacked in the window's bottom right corner, with a close button and, unless permanent, a five-second countdown that pauses while hovered; clicking one runs the plugin's action. While Qord isn't focused the same notification also goes to the desktop (when desktop notifications are on). BetterSessions follows upstream: OS colours, platform badges (upstream's icons; Discord's own mobile icon is drawn with Material Icons' phone, which it matches), exact times, NEW until the page is closed, Rename with a * after the name (empty resets it), names and seen devices kept per account, and a permanent "New session:" notification for each unseen device when it starts or an account connects, which opens Devices. "Background check" looks again when Discord reports a session change, at most once per interval, instead of upstream's timer. Unit tested and checked against the mock, which now has three devices, logs them out, and simulates a new login with `mock_discord.py login`. Not checked against Discord.

99. **List windows, app authorization, action settings; ReviewDB.** Plugins can open list windows (`UiService::openListDialog`, then `updateListDialog` and `closeListDialog`): a title, rows with an avatar, a title, a badge, a small meta line, text and a "…" menu, an empty-state text, an optional "Load more" and an optional input box with a placeholder, each reported back to the plugin; they close when the plugin stops. A new permission, `authorize_apps` ("Ask you to log in to apps with your Discord account"), gives `UiService::authorizeApp`: Qord fetches the app (`GET /oauth2/authorize`), asks you in Discord's words which app wants what ("ReviewDB wants to access your Discord account..."), and only after you confirm posts the authorization and hands the plugin the redirect with its code; nothing is authorized without that click. `NetworkService::request` sends any method with headers and a body (PUT, PATCH, DELETE...). A new setting type, `action`, is a button that calls `onSettingAction`. Profiles can be asked to rebuild their plugin tabs (`refreshProfileTabs()`), and the user context now carries the username. ReviewDB follows upstream: a "User Reviews (N)" profile tab, "View Reviews" for users and servers, the reviews window with votes, reports, blocks, deletes and writing, pages of 50, upstream's errors and toasts, the warning flag, hiding reviews from people you blocked, and the settings' buttons (authorize, manage blocked users, sponsor, website, support server). ReviewDB tokens are kept per account in a secret setting, so in the system keychain, and are sent only in the `Authorization` header to manti.vendicated.dev. Upstream reads `lastReviewId` without ever setting it, so its "You have new reviews on your profile!" toast never fires; Qord records the newest id on the first check and toasts when a newer one appears. Reviews are plain text, and the ban notice has no Appeal button. The mock now answers ReviewDB (the rewrite covers `manti.vendicated.dev`) and Discord's app authorization, with reviews on Ava, you and Qord Dev. Unit tested and checked against the mock (reading, the profile tab, logging in, writing, voting, deleting, unblocking). Not checked against Discord or the real ReviewDB.
