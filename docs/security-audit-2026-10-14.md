## Coverage limits and rejected hypotheses

Native statically linked plugins are trusted native code; service permission checks do not provide process isolation against a malicious compiled plugin. Reviewed host paths intersect declared permissions with grants and constrain manifest IDs. Known secret settings are excluded from JSON and routed to the keychain (memory in mock mode). Future underscore-separated secret-key namespace collisions were considered but no current collision was demonstrated.

The SQL-injection hypothesis was rejected for the inspected queries: values use bindings, and the examined dynamically joined identifiers were numeric conversions/fixed schema names. This is not exhaustive SQL coverage. No immediate additional RTP extension out-of-bounds defect was confirmed in the inspected size checks. No TLS-verification-disabling option was found in the inspected common Discord curl setup; runtime TLS behavior and dependency configuration are unverified. Absence of telemetry was not established for every network path or dependency.

PR #16's initially reviewed identity/keychain rename, release workflow, packaging and compatibility diff, plus the follow-up integration diff, informed this review. Release builds select a commit SHA and publishing alone receives write permission. No confirmed PR16-only exploitable defect was established. Windows/macOS package execution, signing/provenance and migration behavior were not tested. DAVE, FFmpeg, Qt, libsodium and other vendored dependency internals were not exhaustively audited.

## Validation record

The original cloud workspace could not establish the requested execution sandbox:

- Bubblewrap failed with `Can't read /proc/sys/kernel/overflowuid: No such file or directory`.
- Namespace setup failed with `unshare: cannot open /proc/self/uid_map: No such file or directory`.
- Cleared-environment, short-timeout probes did not establish compliant target execution there. Git/GCC availability did not establish a Qt build toolchain.

Source review, edits and non-target Git checks were performed there. `git diff --check` passed during review. No target-controlled build/test/mock execution, real Discord credentials, real keychain entries or deployed probes were used in that workspace.

The follow-up adds `.github/workflows/security-validation.yml` rather than treating cloud location or ordinary CI as proof of isolation. The workflow provisions tools/dependencies before target execution, then starts Bubblewrap with an isolated network/PID/IPC/UTS namespace, read-only source and toolchain mounts, scratch/tmp writable storage, a cleared allowlisted environment, a non-root identity and dropped capabilities. A 35-minute outer timeout plus address-space, CPU, process and file-size limits constrain execution. `tools/check_security_sandbox.py` checks the effective controls before CMake/tests, including no external route, denied source/toolchain writes, allowed scratch writes, environment, capabilities and resource limits. Failure must stop validation. Bootstrap uses privilege only to create namespaces before dropping the target process's privileges; it is not authorization for unrestricted target execution.

Planned CI coverage is Qt 5.15 and Qt 6.10.2 Linux builds, CTest with per-test timeouts, Python tooling tests and generated-doc checks. The application configuration disables the full voice stack while enabling FFmpeg and standalone voice-crypto tests. Dependency/tool provisioning occurs outside the target sandbox and remains a supply-chain trust boundary. Loopback fixtures and fake credentials/keychains are used inside validation.

**Validation chronology (not a rolling check-status assertion):** Sandbox attestation succeeded in both Qt jobs at `f8ac7af823504c0d3cd9abd8f3190d1eab3e89b2` ([run 38719317427](https://github.com/Mknoops/qord/actions/runs/38719317427)); compilation then exposed a missing Opus dependency in a pre-existing stream-audio test under voice-disabled configuration. The Windows jobs also exposed missing curl headers for the new decoder fixture. Both build dependencies were corrected in the subsequent commit. Separately, ordinary Linux and macOS packaging CI at that revision each passed all 93 CTest targets; these runs did not use the audit sandbox and are not isolation evidence. Readiness requires the complete isolated gate and current platform checks to pass; a successful earlier revision is not proof that a later change passed. Ordinary packaging CI is separate evidence and must not be presented as equivalent to the isolated job.

Remaining validation includes Windows/macOS builds and keychain integration, full voice/DAVE integration, visible-link/mock UI checks, decoder fixtures/sanitizers, thread/reconnect stress and realistic large-session compatibility. No real account or production endpoint is required for these checks. Source-review coverage and added regression cases are not a complete security certification.
